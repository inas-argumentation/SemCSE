A Review of Cleanroom Software Engineering
Cleanroom is a software engineering development methodology that is claimed can produce near-zero defect software. The report includes a brief overview of Cleanroom, some examples of its use in industry, and possible future directions for Cleanroom research, as well as a discussion of whether or not Cleanroom is suitable for undergraduate study. Cleanroom 10, 2] is a software engineering methodology that challenges the traditional view that zero-defect software is either unfeasibly expensive or well-nigh impossible for commercial software systems. It comprises a set of practices that cover the software development lifecycle from speciication through to testing. Incremental development Systems are produced as a series of successive increments, each of which adds to the functionality of the existing code. The system is handed over to the testers after the integration of each increment for quality certiication, which must be obtained before further increments can be added. Formal speciication and design Instead of using ambiguous natural language to write speciica-tion and design documents, Cleanroom makes use of a hierarchy of box structures in which the behaviour of system objects is deened mathematically 11, 6]. Methods of formal proof are often used to demonstrate the correctness of Cleanroom designs. Separation of implementation from testing Cleanroom developers do not execute or test any of the code they write (in its purest form developers do not even have access to a compiler when they are writing the code). Instead developers make use of team reviews and inspections to nd defects. Statistical testing Testing is carried out by independent teams who test the software with expected use cases from the system's intended working environment. The principle here is to make the system as reliable as possible, or to put it in more formal terms, to maximise the mean time to failure of the system.
