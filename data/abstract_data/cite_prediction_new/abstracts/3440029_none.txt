Chapter 1 REAL ALGEBRAIC GEOMETRY AND CONSTRAINT DATABASES
The constraint database model can be seen as a generalization of the classical relational database model that was introduced by Codd in the 1970s to deal with the management of alpha-numerical data, typically in business applications (Codd, 1970). A relational database can be viewed as a finite collection of tables or relations that each contain a finite number of tuples. Fig. 13.1 shows an instance of a relational database that contains the two relations Beer and Pub. This database contains tourist information about beers and the pubs where they are served. It also contains the location of the pubs, given in (x, y)-coordinates on some tourist map. Each relation contains a finite number of tuples. Arelational database is usually modeled following a database schema. Aschema contains information on the relation names and on the names of the attributes appearing in relation. In this example, the attributes of Beer are Name, Pub, City and Postal code. The complete schema of the relational database of Fig. 13.1 could be written as Beer(Name, Pub, City, Postal code), Pub(Pub, x, y).
